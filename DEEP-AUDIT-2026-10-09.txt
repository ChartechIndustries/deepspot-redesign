FINDINGS AND CHANGES

1. Saved content needed to behave as one collection throughout the site.
   Previously, homepage, Browse, readers and Fieldbook maintained separate UI
   assumptions. A save in one tab could leave another tab looking out of date.
   site/storage.mjs now normalizes bookmark IDs and notifies every surface after
   a successful write, cross-tab update or browser back/forward restoration.
   Storage failures do not produce a false successful-save state.

2. Fieldbook repeated large empty sections instead of helping people plan.
   It now leads with a restrained aqua trip panel, then Places/Stories tabs,
   counts, search and compact photographic rows. Saved destinations can be added
   to a trip directly. Removing an item preserves keyboard focus. The local-only
   storage boundary is stated clearly. Its header shortcut now appears across
   home, Browse, passport and the shared page shell; mobile exposes it in Menu.

3. Destination photography was unnecessarily restricted.
   The old detail renderer used only the first three stored gallery photos.
   The new photo reader exposes every locally available photo, preserves source
   credits/licensing, supports previous/next and arrow keys, closes with Escape,
   and restores focus. Three previews keep the reading page compact. Single-photo
   and phone layouts have separate, verified control placement.

4. Trip editing could silently lose information.
   The UI and imported/restored state now share a 50-stop limit. Adding a stop
   preserves day assignments and notes. Shared links open an editable copy;
   replacing an existing local trip takes a second explicit save action. A tab
   with stale trip data cannot silently overwrite a newer saved trip. Download
   remains available to recover its edits, including a notes-only trip.
   A shared-trip map action that would have shown the wrong stored route was
   removed. No route-distance or travel-time values have been invented.

5. Contribution drafts needed more reliable continuity.
   Drafts autosave after typing and on field changes. Type switching preserves
   content and removes an irrelevant edit/photo reference. Failed persistence
   stays visible rather than pretending to save. Starting a fresh draft cancels
   pending writes so an old draft cannot reappear on exit. This remains a local
   draft/export workflow, not a live submission endpoint.

6. Several public passport identities were mismatched.
   The original public profile pages were checked individually. The verified
   display names Kris, Lana Velkov, Lydia, Six and SAZ now resolve from their
   existing handles and former name links. Aliases also join saved publisher
   credits to the correct portrait and contributed records. Profile handles and
   member-since values reach the passport renderer. Existing count snapshots
   retain their October 8 capture date; identity verification is October 9.

7. Link rewriting was too optimistic.
   Navigation now consults site/routes.json before converting original detail
   links to local routes. Content not represented locally continues to the
   original page. Original signed-in /profile links lead to /account/, while
   public /user/handle links lead to the appropriate passport. Map links without
   verified local coordinates retain the original destination. Missing local
   content has a meaningful page title and heading.

8. Visual and responsive refinement.
   Retained the halftone Earth, navy/cream backgrounds, green calls to action,
   cobalt accents and the existing What's New palette. Fieldbook uses quieter
   aqua grouping and clearer reading/planning hierarchy. Gallery controls and
   compact saved rows fit 320px and 390px widths. Mobile navigation now exposes
   the same major destinations across Browse and passports. The globe, original
   six-card homepage section and existing bento structure remain intact.

REMAINING INTEGRATION GAPS / RECOMMENDED ORDER

1. Replace fixture fetches with backend content adapters. The local collection
   contains 369 standalone destinations in a 393-record raw catalog, 13 fuller
   spot entries, 9 stories, 7 guides, 10 verified map coordinates and 10 public
   contributor snapshots. These are local fixture counts, not current live-site
   totals. The full catalog and map need current records and verified geometry.

2. Connect authenticated saves, trip persistence and submission APIs. Keep
   server IDs, ownership and revision checks when replacing browser storage.
   Add custom stops, media, visibility and publish/review states to the trip
   backend contract. Keep existing draft recovery during that migration.

3. Supply actual region, rating, condition and sort metadata for Browse. Do not
   infer danger, closure or endangered status from descriptive text. Original
   filter parity requires these fields rather than cosmetic controls.

4. Connect profile publication, username availability, photos, XP/badges,
   memberships, notifications, inbox and moderation to authenticated services.
   Public-profile links are shareable; unpublished browser-local passport edits
   are not server-published profiles. Membership copy remains $1/week, billed
   monthly. Newsletter enrollment remains intentionally unconnected.

5. Extend full detail content, ratings/comments, related items and gallery
   provenance as backend records become available. Current fallbacks route users
   to the original page rather than inventing unavailable information.
